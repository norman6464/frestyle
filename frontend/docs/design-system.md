# FreStyle Design System — 作業を進めるための画面

UI/UX Pro Max と既存の FreStyle 画面・機能を照合して定めた実装ルール。Jira/Confluence の構造を模写するための部品集ではない。目標は「考えを残す → 担当を見つける → 作業を進める → チームに伝える」を、経験の浅い利用者にも既存の開発者にも見通せる順序で示すこと。

## 画面の情報階層

1. **今すること** — ホームでは期限が近い担当作業、チケットでは状態・担当・期限、ナレッジでは本文と共有。最初の視線とTab順に置く。
2. **作業の文脈** — プロジェクト、チケットの親子、関連するページ、更新履歴。作業を判断するのに必要な場合に近くへ置く。
3. **計画・管理** — 見積り、スプリント、版、チーム、アーカイブなど。存在は見つけられるが、主作業を押しのけない。必要時に開く。

大きな一覧は行のままにし、情報と操作を一つのカードに詰め込まない。何もない画面では、空である理由と次の行動を表示する。権限がない場合は操作を無効にするだけでなく、読める値を残す。

## トークンの3層

`src/app/styles/index.css` の `:root` に以下を定義する。値を直接使う画面を増やさず、意味と部品の層を介す。

| 層 | 例 | 役割 |
| --- | --- | --- |
| primitive | `--fs-white`, `--fs-stone-200`, `--fs-blue-600` | ブランドで承認された具体値 |
| semantic | `--fs-page`, `--fs-raised`, `--fs-border`, `--fs-text-strong`, `--fs-action` | 背景・境界・文字・行動の意味 |
| component | `--fs-dialog-surface`, `--fs-menu-border`, `--fs-control-surface` | 部品が依存する公開トークン |

既存の `--color-*` は互換性のため残し、対応するDSトークンへ接続する。配色の変更をページ構成の変更と混ぜない。色だけに状態を頼らず、名称・位置・アイコンまたは文言で補う。

## 部品の選択

- ネイティブのボタン・リンク・単純な入力は `shared/ui` の既存部品を使う。Base UI に全面移管しない。
- ダイアログ・メニュー・少数候補の選択・開閉領域のフォーカスやキーボード操作は Base UI に任せる。見た目は Tailwind とDSトークンで FreStyle 側が管理する。
- `ConfirmModal` は既存の呼び出しAPIを保つ。Escape・外側クリックはキャンセル、初期フォーカスはキャンセルへ。確定は明示操作だけ。
- `FieldSelect` は少数の既定値用。候補が多い人・親チケット探しには検索できる専用Pickerを使う。
- `HeaderUserMenu` の項目は「設定」「ログアウト」に限定。ポータルに描くので、画面・テストはDOM上の親子関係に依存しない。
- 一時的な詳細は `Collapsible` で段階表示する。閉じた内容はTab順に残さない。

## ページへの適用

| 画面 | 最初に見せるもの | 後から開くもの |
| --- | --- | --- |
| ホーム | 期限と進行状況から並べた自分の作業 | 最近見たページ、別の入口 |
| バックログ | 課題名・状態・担当、検索と絞り込み | アーカイブと管理設定 |
| チケット詳細 | 題名・状態・説明・サブタスク・コメント | 計画項目、添付、履歴、アーカイブ |
| ナレッジ | 題名・本文・共有、コメントと提案 | 履歴、テンプレート、カバーなどの設定 |

PCでは本文と属性を2列にできるが、読み上げ・Tab順は本文が先。狭い画面では担当・期限の要約を本文前に置き、編集用の詳細は下段。タッチ対象は44px以上を目安にし、キーボードの `Escape` と閉じた後のフォーカス復帰を検証する。

## 実装と検証の境界

本導入では共通の確認ダイアログ、ヘッダーのユーザーメニュー、チケット状態の選択を Base UI 化し、全画面チケット詳細で属性を段階表示・サブタスクを本文側へ移した。他の独自実装のダイアログ・メニュー・選択をすべて移行したわけではない。移行時は既存のAPI契約、権限、保存のタイミングを維持し、コンポーネントテストとStorybookの実ブラウザ検証を追加する。

## トークンの実体

設計の正本は `design/frestyle-studio-index.md` の ST01（`design/exports/frestyle-studio/og5Tk.png`）。
値の実体は `src/app/styles/index.css` の `:root`、Tailwind への配線は `tailwind.config.js`。

### 書体

`--fs-font-sans` は Noto Sans JP の可変フォント。`@fontsource-variable/noto-sans-jp` を
npm から取り込み、Vite に同一オリジンで配信させる。**Google Fonts の CDN は使えない**
（`index.html` の CSP が `font-src 'self' data:`。CDN からの取得は無言で遮断され、既定書体のまま
描画される）。代替は OS 標準の日本語ゴシックを字幅の近い順に並べ、取得前後で折り返しがずれる幅を
抑える。`tailwind.config.js` の `fontFamily.sans` を差し替えているため、preflight 経由で
アプリ全体の地の書体になる。

unicode-range で 124 枚に分割されているので、5.6MB すべてが配信されるわけではない。日本語の
画面で実際に落ちてくるのは かな帯 79KB + 使った漢字の帯 16KB 前後 × 数枚。ビルド成果物には
woff2 が 156 個（`dist/assets` 合計 8.2MB）入る。`size-limit` は JS だけを見ているので
この増加は予算に出ない。**配信量を測るときは JS の予算とは別に見ること。**

### 状態色

| トークン | 用途 |
| --- | --- |
| `success` / `success-soft` / `success-border` | 完了・保存済み・有効 |
| `danger` / `danger-hover` / `danger-active` / `danger-soft` / `danger-border` | エラー・削除・期限超過（面と枠） |
| `danger-ink` | エラーの文字とアイコン |
| `warning` / `warning-soft` / `warning-border` | 未保存・停止中・下書き・版の閲覧中 |
| `action-soft` | 青の淡い地（選択・強調の面。文字色には使わない） |

`success` / `danger` は ST01 の SUCCESS #4D7C0F / ERROR #DC2626 と同値。

`danger` だけ文字と面を分けている。ST01 の #DC2626 をそのまま淡赤の地 (`danger-soft`) に
載せると 4.42:1 で基準 4.5 を割るため、文字は一段濃い `danger-ink` を使う
（白地 5.94 / `danger-soft` の上 5.92）。面と枠はボードどおり #DC2626。
`success` (白 4.99 / soft 4.59) と `warning` (白 5.02 / soft 4.82) は 1 色で両方満たすので分けない。`warning` はボードに
無いため、画面側が既に使っていた琥珀を名前にしただけで新しい色相は足していない。

導入前は**同じ「エラー」に red-600 / red-700 / red-800 / rose-500〜900 の 4 系統**、
**同じ「成功」に green / emerald / lime の 3 系統**が並行していた。Tailwind 既定パレットの
直書きは `src` から全廃し、色は必ずこのトークンを通す。

ブランド色（`brand-*` = 押せる）と状態色（起きた結果）は役割が違う。混ぜない。
色だけで意味を伝えないこと。エラー・期限超過・未保存には必ず文言かアイコンを添える。

### フォーカスと輪郭

`brand-400` (#60a5fa) は白地 2.33:1 で、枠線・輪郭に要る 3:1（WCAG 2.2 SC 1.4.11）に届かない。
フォーカスリング・選択枠・ドラッグ位置の表示はすべて `brand-600`（白地 5.15:1）を使う。
`brand-400` / `brand-300` は `src` から全廃した。

### 動き

`duration-fast` (120ms) / `duration-base` (180ms) / `duration-slow` (260ms) の 3 段だけ。
fast は状態の切り替え、base は出現・移動、slow は面の入退場。退場は入場より短くする。
緩急は `ease-fs-standard` / `ease-fs-decelerate` / `ease-fs-accelerate`。

動きを減らす設定への対応は `index.css` の `prefers-reduced-motion` で一括して行う。
部品ごとに `motion-reduce:` を付けて回らない（付け忘れが必ず出る）。

### 文字サイズ

ST01 の指定は本文 14–18px。`role="alert"` / `role="status"` の文言は本文として扱い、
12px・11px だったものを 14px に揃えた。12px は補助ラベル・バッジ・メタ情報に限る。

### アイコン

`src/shared/ui/icons/` に FreStyle 専用の線アイコン一式（`FsIcon`、46 種）と、空状態・失敗の絵
（`FsIllustration`、4 種）を持つ。形の定義は `fsIconParts.ts`、描くのは `FsIcon.tsx`、
「`className` を受け取る部品」として渡すための工場は `fsIconFactory.tsx`。

* 線幅 1.75・端と継ぎ目は丸・24 の格子・外周 1.5 は空ける。heroicons（1.5）より一段太く、
  16px まで縮めても線が消えない。設計ボード ST02 / ST12 の下部ナビの絵に合わせた。
* 既定は飾り（aria-hidden）。意味を持たせるときだけ `title` を渡す（role="img"）。
  テストは `data-icon` で引く。
* **状態は色ではなく形で区別する**（`STATUS_ICON`）。未着手＝空の輪、進行中＝輪の中に点、
  完了＝輪の中に印。色は利用者が管理画面で選ぶので、どんな色でも形と名前で読める。
* **優先度は向きで読む**。高＝上へ 2 つ、中＝水平 2 本、低＝下へ 1 つ。
* 空状態の絵は二色刷り。面は `--fs-action-soft`、線は文字色、差し色 `--fs-action` は 1 か所だけ。
  生の色値を持たないので配色の変更に追随する。

heroicons は残っている（57 ファイル）。殻（全体ナビ・ヘッダー・ユーザーメニュー）、バックログ配下、
状態ピル、共通の選択欄と空状態を置き換えた。残りは触った画面から順に寄せる。
**同じ画面に 2 系統のアイコンを混ぜないこと**（線の太さが違うのが一目で分かる）。

ファイル名を `FsIcon.tsx` と大文字小文字だけ違う名前にしてはいけない。macOS は区別せず、
片方がもう片方を上書きする（実際に起きた）。
